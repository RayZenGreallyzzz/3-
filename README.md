# Rig & Weapon Studio

Android + PC 3D-мастерская для просмотра анимированных персонажей и точного позиционирования оружия.

## Возможности
- Стартовое меню со заставкой, экраном загрузки и быстрым выбором персонажа/оружия/пустой сцены.
- Импорт GLB, GLTF, FBX, OBJ, DAE, STL, PLY; анимаций GLB/GLTF, FBX и поддерживаемых DAE.
- Воспроизведение, пауза, остановка, скорость, перемотка и выбор клипа анимации.
- Список костей скелета, фильтр, отображение костей на персонаже.
- Загрузка оружия из отдельного файла, привязка и отвязка от выбранной кости.
- Позиция/вращение/масштаб X/Y/Z в 3D-манипуляторе и цифровых полях.
- Копирование и сохранение JSON с координатами относительно кости и мировыми координатами.

## Запуск на компьютере
Node.js 22+:
```sh
npm install
npm run dev
```
Сборка веб-приложения: `npm run build`.

## APK — GitHub Actions
Сборка `Build Android APK` запускается после commit в ветку `main` или вручную:
**Actions → Build Android APK → выбранный успешный запуск → Artifacts → Rig-Weapon-Studio-APK**.
В архиве находится `app-debug.apk` (debug сборка для проверки).

## Управление
На ПК мышь: вращение камеры левой кнопкой, панорама правой, увеличение колесом. На телефоне один палец вращает камеру, два — масштабируют/перемещают. После импорта оружия выбирайте в списке кость руки, нажимайте **Привязать**, двигайте оси гизмо или вводите числовые координаты и проверяйте их во время анимации.

В экспортируемом JSON поле **local** — координаты относительно текущей кости (правильное значение для повторного крепления оружия), **world** — в мировой системе координат, меняется при анимации. Значения экспортируются без округления; видимые числовые поля округлены только для удобства.

## Ограничения
- Тяжёлые модели могут работать медленно на слабых Android устройствах.
- Сложные FBX/DAE могут требовать конвертацию в GLB для корректного отображения материалов.
- Для .gltf с .bin и текстурами выбирайте внешние файлы вместе с основной моделью.
- OBJ использует упрощённые материалы, MTL автоматически не читаются; STL/PLY без анимаций.
- Экспорт использует систему координат Three.js (Y вверх); при интеграции в Godot конвенции осей необходимо согласовать.
- Редактирование весов скининга, костей и ключей анимаций в текущую версию не входит.
- `public/logo.svg` — временное оформление. Оригинальную иконку можно добавить в проект отдельным изображением.

Стек: Vite + Three.js + Capacitor 7. Лицензия MIT.

## Android сохранение v0.3

В Android WebView ссылки вида `<a download>` не гарантируют создание файла. Теперь используется нативный плагин `NativeFileSaver`: GLB или JSON передаются порциями во временное хранилище приложения, затем открывается системный выбор **места и имени файла** (`ACTION_CREATE_DOCUMENT`). В стандартном Android DocumentsUI пользователь также может создать новую папку, если используемый поставщик файлов поддерживает это действие. После выбора файл копируется потоком в указанное место. Для отмены или ошибки временный файл удаляется. Плагин встраивается в генерируемый Android-проект шагом GitHub Actions. На настольных браузерах используется системный `showSaveFilePicker` при наличии, иначе браузерная загрузка.

Возможна несовместимость отдельных исходных FBX-анимаций с экспортом GLB; в этом случае приложение повторяет экспорт без анимаций и показывает явное предупреждение, а не утверждает, что анимации сохранены.

## Повторный импорт составного GLB (после теста APK №16)
- При сохранении GLB редактор добавляет метку к узлу оружия в `userData`, переносимую как `extras` в glTF.
- При повторном импорте такого файла приложение находит дочернее оружие, восстанавливает его в панели «Оружие», показывает текущую кость и позволяет двигать/вращать его без нового импорта.
- Для ранее созданных файлов `*_weapon.glb` без метки доступно осторожное автоматическое обнаружение геометрии, прикреплённой к костям кисти/руки. Для других файлов такое обнаружение отключено, чтобы не принять части персонажа за оружие.
- При открытии составного GLB второй отдельный экземпляр оружия не добавляется; существующее редактируемое оружие заменяется встроенным из файла.


## Руки и захват оружия (v0.4)
Раздел «Поза рук»: правая/левая рука, ключица/плечо/локоть/кисть, локальные повороты X/Y/Z с мягким редакторским ограничением углов. Поддерживается автоматическое сопоставление большинства Mixamo-костей и ручной выбор для произвольных ригов. Отдельный сброс сустава и стороны.

Поправки — **локальные вращения поверх анимации**, без перемещения костей, геометрии, весов или таза/ног. Это не IK и не исправление некачественных весов скининга. Во время проигрывания базовая поза восстанавливается перед обновлением AnimationMixer и повторно корректируется после него: накопления вращений не происходит. При экспорте к QuaternionKeyframeTrack добавляются поправки; нестандартные типы треков пока не гарантируют правильный результат. Проверяй GLB повторным открытием. Для сохранения используется тот же системный выбор папки Android.

Автотесты: `npm run test:pose` (распознавание костей, отсутствие накопления углов, сохранение ключевых кадров).

## v0.5 — отдельное положение оружия и поправки рук для каждой анимации

Причина жалобы при импорте нескольких действий: раньше у персонажа было одно локальное положение оружия на **все** клипы, а поправки `ArmPoseController` запекались одинаково в каждую анимацию. В новой версии для каждого клипа отдельно хранятся и сохраняются:
- Положение, вращение, масштаб оружия относительно **той же привязанной кости руки**.
- Вращения ключицы, плеча, предплечья и кисти, внесённые через редактор позы.

Нажми нужную анимацию (`Idle`, `Run`, `Attack`), настрой оружие и нажми **«✓ Запомнить положение»**. При переключении на другую анимацию несохранённые изменения оружия запоминаются автоматически. При возвращении к клипу восстановится его собственное положение и поправки рук. Если ничего не настраивали для данного клипа, используется исходный захват; «Вернуть исходное» очищает профиль **только текущей** анимации.

Экспорт GLB записывает отдельные `position/quaternion/scale` каналы для оружия в каждом клипе; простая общая локальная трансформация этих результатов не обеспечивала. Метаданные профилей хранятся в glTF `extras` оружия для повторного редактирования в приложении, а сам GLB содержит реальные анимационные ключи, пригодные для Godot. Редактирование рук запекается только в выбранную анимацию вместо всех. Исходные клипы не меняются. Если выбранная кость крепления оружия поменяется на другую, профили очищаются: GLB не умеет менять родителей одного узла по времени. Для переключения оружия из правой в левую руку нужна отдельная игровая логика/специальный риг. Динамическое перемещение оружия **внутри одного клипа по отдельным кадрам** пока не поддерживается; поддерживаются отдельные статические локальные положения **для разных клипов**.

Тесты `npm run test:pose` теперь покрывают и клиповые профили оружия.

## v0.6 — оружие на спине / поясе, доставание и убирание в руку

В разделе «Положение оружия» добавлен **редактор ключей крепления**, использующий **уже имеющиеся кости** модели. Вместо создания ненужных дополнительных сокетов список предлагает `Рука` (Hand/Wrist), `Спина` (Spine/Chest), `Пояс` (Hips/Pelvis), `Выбранная кость` (список скелета). Если нужной кости нет — редактор покажет предупреждение, не привяжет оружие к случайной кости.

Как пользоваться: загрузи персонажа с несколькими анимациями и оружие, выбери кость руки и нажми «Привязать». Затем выбери клип, например `DrawWeapon`, поставь на шкале **0.00 с**, выбери «Спина», нажми «Поставить у кости», подгони оружие в 3D и **«Ключ на этом кадре»**. Перемотай, например, на **0.70 с**, выбери «Рука», нажми «Поставить у кости», подгони рукоять и запиши второй ключ. При просмотре оружие следует точке спины до начала перехода, затем плавно перемещается между ключами, а после второго ключа следует кисти. С тем же способом можно делать `SheatheWeapon`, `Idle` с мечом на поясе и другие действия. Ключи независимы для каждого клипа, их можно выбрать в списке по времени и удалить. Для анимаций без переходов продолжает работать «Запомнить положение» из v0.5.

**Как это реализовано:** glTF/GLB не допускает динамического изменения родителя узла во время анимации. Поэтому оружие остаётся дочерним узлом кости руки, но при просмотре редактор вычисляет нужную **мировую** позицию от выбранной кости (спина/таз/рука). При экспорте исходные кадры выбранных клипов просчитываются через `THREE.AnimationMixer` до 30 раз в секунду и конвертируются в **локальные** дорожки оружия `translation/rotation/scale` относительно постоянной кости-родителя. Такие ключи непосредственно воспроизводятся Godot, без плагинов или JSON-обработчика в игре. В glTF `extras` остаётся информация об исходных точках для следующего открытия файла в Rig & Weapon Studio. Треки остальных анимаций не затрагиваются.

**Проверка целостности:** редактор проверяет число клипов в реально экспортированном GLB и наличие `translation/rotation/scale` дорожек оружия для каждого. В случае несовместимых анимаций, если оружие привязано, экспорт **останавливается с ошибкой**, а не молча сохраняет GLB без записанных движений. Оригинальная модель и отдельные файлы не изменяются.

**Ограничения:** программа берёт опорную точку из существующей кости (не распознаёт автоматически расположение ножен на конкретной броне), поэтому угол и позицию клинка на спине/поясе требуется уточнить вручную. Переход — плавное пространственное перемещение между позициями в указанные моменты, без IK-процедур для рук и пальцев; анимация рук должна уже содержаться в выбранном клипе. Внешнюю позицию меча удобно проверить после экспорта в Godot. Наиболее длительные анимации ограничены 600 точками сэмплирования, чтобы избежать зависания мобильных устройств.
